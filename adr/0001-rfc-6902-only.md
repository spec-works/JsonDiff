# ADR 0001: RFC 6902 Only - No Format Options

## Status

Accepted

## Context

JSON differencing and patching libraries often support multiple formats and standards:

1. **RFC 6902 (JSON Patch)** - Standard operations format (add, remove, replace, move, copy, test)
2. **RFC 7386 (JSON Merge Patch)** - Simpler merge-based format
3. **Proprietary formats** - Library-specific diff representations
4. **Non-standard extensions** - Vendor-specific operations

Popular libraries like JsonDiffPatch expose multiple formats through configuration options, allowing consumers to choose which format to use. While this flexibility may seem beneficial, it creates several problems:

1. **Vendor lock-in**: Using proprietary formats makes code non-portable
2. **Interoperability issues**: Different formats cannot be exchanged between systems
3. **Specification drift**: Non-standard features encourage departure from specifications
4. **API confusion**: Multiple options increase cognitive load and decision fatigue
5. **Testing complexity**: Must test multiple code paths for different formats
6. **Migration difficulty**: Switching between formats requires code changes

### SpecWorks Philosophy

From the SpecWorks vision, components are:
- Generated from **published standards**
- Focused on **specification compliance**
- Designed for **interoperability**
- Avoiding **proprietary formats**

The goal is to provide developers with reliable, standards-based components that work consistently across languages and systems.

## Decision

The SpecWorks.JsonDiff component SHALL:

1. **Support RFC 6902 ONLY**
   - No RFC 7386 (JSON Merge Patch) support
   - No proprietary diff formats
   - No configurable output formats
   - No non-standard extensions

2. **Enforce this constraint at the API level**
   - No format parameters in method signatures
   - No configuration options for output format
   - Clear documentation that this is RFC 6902 only

3. **Use standard .NET types**
   - `System.Text.Json.Nodes.JsonPatchDocument` for patches
   - `System.Text.Json.Nodes.JsonNode` for input documents
   - No custom patch formats or representations

## Implementation

```csharp
namespace SpecWorks.JsonDiff
{
    /// <summary>
    /// Generates RFC 6902 compliant JSON Patch documents.
    /// This component strictly implements RFC 6902 and does not support
    /// other formats such as JSON Merge Patch (RFC 7386) or proprietary formats.
    /// </summary>
    public interface IJsonDiffGenerator
    {
        /// <summary>
        /// Creates an RFC 6902 JSON Patch document representing the
        /// differences between source and target documents.
        /// </summary>
        /// <param name="source">The source JSON document</param>
        /// <param name="target">The target JSON document</param>
        /// <returns>A JsonPatchDocument containing RFC 6902 operations</returns>
        JsonPatchDocument CreateDiff(JsonNode source, JsonNode target);

        // NOTE: No CreateMergePatch() method
        // NOTE: No format parameter
        // NOTE: RFC 6902 only, always
    }
}
```

### What This Prevents

```csharp
// ❌ These APIs will NOT exist:
jsonDiff.CreateDiff(a, b, DiffFormat.Custom);
jsonDiff.CreateMergePatch(a, b);
jsonDiff.SetFormat(DiffFormat.Proprietary);

// ✅ Only this API exists:
JsonPatchDocument patch = jsonDiff.CreateDiff(source, target);
```

## Consequences

### Positive

1. **Specification compliance**: 100% RFC 6902 conformant
2. **Interoperability**: Patches work with any RFC 6902 compliant system
3. **Simplicity**: Single API surface, no configuration needed
4. **Predictability**: Output format is always known
5. **Future-proof**: When SpecWorks generates its own implementation, no non-standard features to port
6. **Standards alignment**: Reinforces SpecWorks' specification-focused philosophy
7. **Clear intent**: API explicitly communicates RFC 6902 compliance

### Negative

1. **Limited flexibility**: Cannot support other patch formats
2. **No merge patch**: Developers wanting RFC 7386 must use another library
3. **Single purpose**: Component does one thing only

### Mitigation

- **Documentation**: Clearly state RFC 6902-only scope in README
- **Alternatives**: Document when RFC 7386 might be more appropriate
- **Separate component**: If RFC 7386 support is needed, create a separate `SpecWorks.JsonMergePatch` component

## Examples

### Allowed Usage

```csharp
using SpecWorks.JsonDiff;
using System.Text.Json.Nodes;

var source = JsonNode.Parse("{\"name\":\"Alice\",\"age\":30}");
var target = JsonNode.Parse("{\"name\":\"Alice\",\"age\":31,\"city\":\"NYC\"}");

var generator = new JsonDiffGenerator();
JsonPatchDocument patch = generator.CreateDiff(source, target);

// Output: RFC 6902 compliant operations
// [
//   { "op": "replace", "path": "/age", "value": 31 },
//   { "op": "add", "path": "/city", "value": "NYC" }
// ]
```

### Not Allowed

```csharp
// ❌ This pattern is intentionally NOT supported:
var options = new DiffOptions { Format = DiffFormat.MergePatch };
JsonPatchDocument patch = generator.CreateDiff(source, target, options);
```
